Authentication, Authorization, and Security Flow

Based on code in auth-service and spendwise-service.

High-Level Architecture

auth-service

Handles registration, login, refresh, logout and JWT creation. Uses Spring Security with a custom JwtAuthenticationFilter.

Context Path
/authservice
Public Endpoints
/api/auth/**
JWT Claims
sub (username), userId, roles

spendwise-service

Consumes JWTs from auth-service. Validates tokens and builds a Spring Security authentication with roles.

Context Path
/expenseservice
Protected Endpoints
All except /error and OPTIONS /**
Method Security
@EnableMethodSecurity + @PreAuthorize

Login Flow (auth-service)

1. Client sends POST /authservice/api/auth/login with username/password.
2. AuthController.login() calls AuthService.authenticate().
3. AuthenticationManager authenticates via UserDetailsService (CustomUserDetailsService loads User).
4. On success, JwtService.generateToken() builds JWT with roles claim and optional userId.
5. A refresh token is created and stored in DB; response includes both access token and refresh token.

Register Flow (auth-service)

1. Client sends POST /authservice/api/auth/register.
2. AuthService.register() checks uniqueness, encodes password with BCryptPasswordEncoder.
3. Assigns role ROLE_USER if missing.
4. Generates JWT + refresh token and returns response.

Refresh and Logout (auth-service)

Refresh: POST /authservice/api/auth/refresh validates stored refresh token, then issues a new access token.
Logout: POST /authservice/api/auth/logout with X-Refresh-Token marks refresh token as revoked.

Security Internal Flow (auth-service)

Filter Chain

SecurityConfig sets stateless sessions, disables CSRF, allows /api/auth/**, and adds JwtAuthenticationFilter before UsernamePasswordAuthenticationFilter.

1. For protected endpoints, JwtAuthenticationFilter checks Authorization: Bearer <jwt>.
2. It extracts username, loads UserDetails, validates token, then sets SecurityContextHolder authentication with authorities from roles/permissions.
3. Method security is enabled via @EnableMethodSecurity, so any future @PreAuthorize annotations are enforced.

JWT Authentication Filter Flow (spendwise-service)

1. JwtAuthenticationFilter reads the Authorization header.
2. If header starts with Bearer , token is validated via JwtService.isTokenValid().
3. Username is extracted from sub, roles are read from roles (fallback: authorities).
4. Creates UsernamePasswordAuthenticationToken using extracted roles and sets it in the SecurityContext.
5. Request proceeds to controllers with authenticated principal and authorities.

Method-Level Security (spendwise-service)

Enabled

Method security is enabled with @EnableMethodSecurity in SecurityConfig.

Controller Usage
@PreAuthorize("hasRole('ADMIN')") // create/update/delete categories
@PreAuthorize("hasRole('ADMIN','USER')") // get all categories
@PreAuthorize("hasAnyRole('ADMIN','USER')") // expense details & reports
Note: hasRole('ADMIN','USER') is not standard Spring Security syntax; usually you should use hasAnyRole('ADMIN','USER'). The code currently has a mix of both, which may affect authorization results.

Token Compatibility Between Services

1. auth-service signs JWT with shared security.jwt.secret (same in both application.yaml files).
2. spendwise-service validates token signature and expiry using the same secret.
3. Roles embedded by auth-service are used by spendwise method security annotations.
